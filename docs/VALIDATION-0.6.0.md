## 真实模型

`LiveDeepSeekTest` 对官方 `deepseek-flash` 分别调用 Chat Completions 和 Anthropic Messages：识别红色图片，接收工具结果，再计算 20+22 并调用工具返回 42。两种协议均通过，用量非零。

另用真实 `deepseek-v4-pro` 检查 `thinking=enabled`、`reasoning_effort=max` 与工具调用。三盒错标签问题得到正确结论，HTTP 200，包含推理内容。这是参数与基本推理联通检查，不是模型能力评分。

`tools/live-phone-smoke.mjs` 把真实模型接入 Android 无障碍、截图、确认卡片与运行面板，5 项检查全部通过：

- 从两个相似姓名中打开“测试联系人”，填写指定中文草稿，不发送。
- 普通导航与输入不另弹确认，只有最初批准电脑任务的卡片。
- 第二个任务发送已有草稿，发送确认一次，页面只收到一次发送。
- 新增正文气泡、输入框清空，任务结束后面板移除。

实际页面事件为 `open`、`typed:真实模型联调：明天十点见`、`sent:真实模型联调：明天十点见`。

| 打开联系人并填写草稿 | 41.475 秒 | 18.066 秒 | 2 / 2 |

表中为桌面发起到收到结果的时间，包含测试脚本批准卡片的等待。应用内记录的两次模型等待分别为 12.970 秒、11.832 秒；总耗时分别为 16.218 秒、14.350 秒，不含最初任务授权。
这是同一天、同一模拟器、同一代理和任务的单次对照。提速前为本轮早期实现，不能视为 0.5.0 基准；网络与服务端响应有波动，不能用这两次任务推算普遍加速比例。

测试聊天页在本地，不联系真实用户。这里使用 API 密钥验证，账号登录令牌仍只做协议回归；微信真人账号、真机与不同厂商系统没有完成验证。

## 设备回归

`tools/device-smoke.mjs` 的 38 项检查通过，模型回复由本地夹具提供。覆盖真实手势、中文输入、重名、旧截图编号、局部放大、未知勾选状态、发送核验、禁止重复发送及面板停止、正常结束和错误清理。
新增两步打开会话并填写草稿、连续计划不能发送、目标不存在即停止三项检查。

脚本临时替换测试配置、代理和端口映射，结束后恢复；不保存原配置、令牌或密钥。修正了 Android 缓存代理未随字段删除而清空的问题；本地测试页禁用浏览器自动翻译，避免翻译条遮挡目标。

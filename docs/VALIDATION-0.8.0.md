本轮增加与调整的断言包括：

- 页面稳定等待：安静页面 60 毫秒，持续事件流最多 300 毫秒；取消立即终止等待，旧事件不产生额外延迟。
- 截图按剩余间隔等待，首张不等待，取消不会占用后续时隙。
- 失败记录显示“继续任务”，保留完整原始目标；旧版七字段历史兼容。分别保留最近 12 个未完成任务，完成其他任务不会丢失原进度。
- 中断后用待发送摘要值重新核验，已有气泡不冒充新发送；未核验结果仍阻止重发。没有旧版摘要值时保留人工核对要求。
- 输入框资源 ID 或位置改变、发送后输入框消失、正文在无障碍描述中、多段正文和气泡延迟出现的核验。
- 保留重复正文、额外文字、大小写变化、发送中、失败标记、换联系人、重名、过期节点、未知勾选和取消测试。
- 连续联系人导航每次动作后读取新结果，不重复读同一帧；中间步骤不重复编码截图，目标派发前仍重新校验。

## 刷新与截图

`Settler` 原为安静 300 毫秒、最多 3 秒，现为安静 60 毫秒、最多 300 毫秒。收到持续刷新事件不会无限延长等待。
读取前刷新根节点；切页时若只有空根节点，在剩余预算内短暂复查，不直接判成缺失联系人。动作没有立刻产生新内容时做有限次直接读取，不再次等待完整安静期。
发送后用 80、120、200 毫秒的间隔检查新消息，出现依据便停止。未看到依据时不重发。

截图限频与读控件树分别处理。AOSP 的显示截图最小间隔为 333 毫秒，参见[平台实现](https://android.googlesource.com/platform/frameworks/base/+/main/core/java/android/accessibilityservice/AccessibilityService.java)。本项目按 350 毫秒安排截图，只等剩余间隔，限频后重试从固定一秒改为 350 毫秒。
300 毫秒是页面稳定等待上限；完整工具返回还包含 Binder 读取、图片编码、传输及可能的截图限频。模型响应另计，不宣称全部请求都在 300 毫秒内结束。

## 恢复与发送

失败记录的“继续任务”直接恢复原目标和已完成步骤，不把失败摘要当作新对话。恢复时先让 dsh 页面退到后台，按保存的包名回到原应用并读取当前界面，不清空应用或重新从首页执行。
历史标题最多 300 字，失败目标另存原文，避免长任务恢复时丢掉末尾要求。超出最近 12 个未完成任务或旧版未保存进度时，仅能用原目标与失败摘要重新核对剩余步骤。

待核验发送保留正文 SHA-256、长度、原会话摘要和发送前气泡数量；不复制正文或屏幕转储。用户输入的原始任务仍按本机历史规则保存。
发送按钮和输入框不要求一直存在：新增精确正文且草稿清空，或同一会话中输入框已经移除，才通过。新失败标记、发送中或数量未增加仍不通过。
